# Sources of truth for a Brazilian federal legislation mirror

Research date: 2026-10-20/21 (UTC). All requests were anonymous GETs from a residential Mac, with no contact info in any request. Raw captures are in the git-ignored `.scratch/raw-2026-10-20/`.
Anything marked **UNVERIFIED** was not observed first-hand.

## TL;DR recommendation

| Role | Source | Why |
|---|---|---|
| **Primary text (all norms)** | Planalto `ccivil_03` pages (`*compilado.htm` where one exists, otherwise the act page, which is updated in place) | It is the most current source: CF has EC 140/141 (DOU 16/10) as of 19/10, CLT through Lei 15.377/2026, CPC through Lei 15.484/2026. Unlike normas.leg.br, it handled EC 141's **deferred vigência** correctly. Public domain (Lei 9.610/98 art. 8º IV). |
| **Structure, ids, point-in-time history, cross-check** | Senado **normas.leg.br** JSON-LD API (`/api/public/normas?urn=…&tipo_documento=maior-detalhe`); **undocumented**, reverse-engineered from the SPA bundle v2.7.25 | Per-dispositivo tree with LexML URNs and every historical version, under CC BY 4.0. It is current for the CF but **stale for codes**: CC lacks the repeal of art. 757 ff. by Lei 15.040/2024; CPC lacks Lei 15.484/2026. CLT, CDC and CTN are **not articulated** there. It also mis-dates deferred vigência. |
| **Second cross-check for codes** | Câmara LEGIN `…-normaatualizada-pe.html` | Its CLT compilation matches Planalto's latest amending law (15.377/2026). UTF-8 HTML generated from Word. |
| **Change triggers** | Planalto `quadro_emc.htm` (+ ETag), Senado dadosabertos `/legislacao/{id}` `vides` list | The EC index was updated on DOU day. The Senado `vides` already lists EC 140/141 (secondary trigger only; `quadro_emc.htm` is the catalogue). |
| **Spot-check only** | ctresb/leis (MIT, very active), LawCodex/br (no licence, one-shot run 2026-10-11/12), abjur/constituicao (frozen 2020) | None of them is per-article or authoritative. |

Design implication: each dispositivo needs **current wording + pending wording with a start date** (see §5, EC 141). It also needs its **own LexML-Parte-3 id**, keeping the normas.leg.br id as an alias (see §3).

## 1. Planalto (planalto.gov.br/ccivil_03)

### Access, blocking, throttling

The F5/TS WAF filters by **User-Agent**. Cookies observed: `f5_cspm`, `TS01bca3bd`. Results per UA:

| UA | Result |
|---|---|
| curl default, `python-requests/2.32`, empty UA, `lex-mirror-bot/0.1` | `curl: (56) Recv failure: Connection reset by peer` |
| `Wget/1.21` | timeout (no bytes in 20 s) |
| `Mozilla/5.0` | 200 |
| `Mozilla/5.0 (compatible; mirror/0.1)` | 200 |

- **Recommended UA:** `Mozilla/5.0 (compatible; <name>/<ver>)`, with no URL or email. LawCodex documents the same firewall behaviour and caps itself at 4 concurrent requests.
- **No throttling seen:** 20 back-to-back conditional GETs all returned 304.
- `robots.txt` → 404, so there is none.
- **Datacenter / GitHub Actions IPs: UNVERIFIED.** All tests ran from a residential IP, and F5 can also filter by IP reputation. Add a smoke-test step to the first Actions run and keep a fallback (self-hosted runner or proxy) in mind.

### Change detection

The server is Apache-style and sends `ETag` + `Last-Modified`, no gzip, `Content-Type: text/html` with **no charset**. Sample headers:

```
constituicao.htm         Last-Modified: Mon, 19 Oct 2026 16:20:05 GMT  ETag: "1c2b8c-65e33e305558b"  1,847,715 B
constituicaocompilado.htm Last-Modified: Mon, 19 Oct 2026 16:20:10 GMT  1,507,134 B
del5452compilado.htm     Last-Modified: Fri, 09 Oct 2026 16:17:05 GMT  ETag: "175baf-65d6aaddb6666"
l10406compilada.htm      Last-Modified: Thu, 23 Apr 2026 23:10:05 GMT  ETag: "e12e4-65028bfb0defb"
l8078compilado.htm       Last-Modified: Tue, 13 Oct 2026 09:50:35 GMT
quadro_emc.htm           Last-Modified: Fri, 16 Oct 2026 17:46:35 GMT  ETag: "147d6-65df8bee18252"
```

- `If-None-Match` and `If-Modified-Since` both return **304**.
- Last-Modified moves without substantive change. For example, `emc140.htm` shows 19 Oct for an act published 16 Oct.
- **Rule:** use ETag as a cheap prefilter. The real change signal is a hash of the normalized text of each dispositivo.

### Encoding

- **No `<meta charset>`** on any page tested (CF, CLT, CC, CDC, CTN, CPC, LC 95).
- The bytes are **windows-1252**, not ISO-8859-1. C1 bytes 0x91–0x96 (curly quotes, en dash) appear in every file, e.g. CTN has 65 × 0x96. Decode as cp1252.
- Numeric references such as `&#150;` and `&#145;` (seen in LC 95) need the HTML5 windows-1252 remap.
- The files are hand-edited FrontPage/Word HTML with malformed tags (e.g. `</p<a>` in the CF) and CRLF/LF mixed, so use a lenient parser.

### How old wording is marked: inconsistent across pages

| Page | `<strike>` | `<s>` | CSS `line-through` | Notes |
|---|---|---|---|---|
| CF `constituicao.htm` | 777 | 0 | 7 | Full history; old wording struck next to new |
| CF `constituicaocompilado.htm` | 3 (residual) | 0 | – | Clean current text |
| CLT `del5452compilado.htm` | 106 | 0 | 10 | "compilado" but still has struck text |
| CC `l10406compilada.htm` | 1 | 1 | 0 | Old wording omitted |
| CDC `l8078compilado.htm` | 0 | 2 | 0 | |
| CTN `l5172compilado.htm` | 1 | 0 | 0 | |
| CPC `l13105.htm` (act page, updated in place) | 44 | 0 | 35 | Struck text via both tag and CSS |

- **Rule:** drop `<strike>`, `<s>`, `<del>` and any element with `text-decoration: line-through`, even on "compilado" pages.
- Keep the provision label when only an annotation like "(Revogado)" remains. LawCodex documents the same approach.

Real snippets:

- CF art. 7 XIII:

  ```
  XIII - duração do trabalho normal não superior a 8 (oito) horas diárias e 40 (quarenta) horas semanais, … (Redação dada pela Emenda Constitucional nº 141, de 2026)
  ```

- CC art. 3º:

  ```html
  Art. 3<sup><u>o</u></sup> São absolutamente incapazes … <a href="../../_Ato2015-2018/2015/Lei/L13146.htm#art114">(Redação dada pela Lei nº 13.146, de 2015)</a> <a …#art127>(Vigência)</a>
  ```

- CC art. 3º I: `I - <a …>(Revogado)</a>` (the label survives, the text is gone).

- **Deferred vigência** (CF art. 7 XV): the old wording stays as the current text and is flagged as such:

  ```
  XV - repouso semanal remunerado, preferencialmente aos domingos; (Vide Emenda Constitucional nº 141, de 2026) (Vigência)
  ```

  "(Vide EC …) (Vigência)" is the trigger for the "pending wording" schema slot.

### Other markup inconsistencies

- **Article ordinals vary by page:** `Art. 1º` (CF, CTN, CPC), `Art. 1°` with a degree sign (CDC, 7 hits), `Art. 1<sup><u>o</u></sup>` (CC), and CLT's `Art. 482 -` with a dash.
- Inciso separators are mostly `-`, sometimes `–` (CTN 65, CC 23).
- **Anchors:** the CF has `<a name="art5">`-style anchors (4,706 named anchors), plus a newer structured scheme on 278 articles: `cf-88-parte-1-titulo-2-capitulo-1-artigo-5`. That scheme is itself inconsistent for lettered articles (`artigo-103-a` vs `artigo-103a`).
- ADCT anchors: `adct`, `adctart1`, `art1adct`.
- CC and CDC have almost no anchors (8 and 0).
- **Conclusion:** markup is not consistent between the CF and the codes, or even between codes. Plan for one tolerant parser plus per-norm fixtures.

## 2. Senado Federal

### 2a. dadosabertos (legis.senado.leg.br/dadosabertos): metadata, not text

The OpenAPI spec is at `https://legis.senado.leg.br/dadosabertos/v3/api-docs`. Legislation endpoints:

```
GET /dadosabertos/legislacao/lista?tipo=CON&ano=1988      -> {"id":"579494","tipo":"CON-v","descricao":"Constituição Federal Vigente","norma":"CON-1988-10-05",…}
GET /dadosabertos/legislacao/{codigo}                       (e.g. /legislacao/579494, Accept: application/json, 653 KB)
GET /dadosabertos/legislacao/urn?urn=urn:lex:br:federal:constituicao:1988-10-05;1988   (same document by URN)
GET /dadosabertos/legislacao/{tipo}/{numdata}/{anoseq}, /tiposNorma, /tiposVide, /termos, /classes
```

- The detail document holds `identificacao`, `publicacoes`, `vides` (641 entries for the CF), `edivs` and `disps` (per-dispositivo relations, e.g. `"Art. 7, caput, Inciso 13"`), plus `urlDocumento` → normas.leg.br.
- **It has no article text.**
- It is **up to date:** the vides already list `Emenda Constitucional nº 140 de 16/10/2026` and `nº 141 de 16/10/2026`.
- It is **not an EC catalogue:** only 121 distinct ECs are listed under the CF record, against 141 real ones. ECs that touch only the ADCT (a separate norm, id 604119) or have only autonomous provisions are not listed there. Use it as a secondary change trigger only.

### 2b. normas.leg.br: articulated JSON-LD (the structured source)

The API is **undocumented**. It was found by reading the SPA bundle (`main.*.js` v2.7.25, chunk `987.*.js`), not a published contract, so it can change without notice. The job must assert the response shape on every run and fail loudly. Endpoints:

```
GET https://normas.leg.br/api/public/metadados/simples?urn=<URN>                       (thin metadata)
GET https://normas.leg.br/api/public/normas?urn=<URN>&tipo_documento=maior-detalhe     (full tree)
GET https://normas.leg.br/api/public/binario/<uuid>/texto                              (HTML renditions)
```

**Full CF fetch:** 4,798,138 bytes in 1.2 s.

- Top level: `@context` schema.org, `license`/`sdLicense` = **CC BY 4.0**, `dateModified: 2026-10-16`, `sdDatePublished: 2026-10-19`.
- 3,093 nodes. By type: inciso 1298, paragrafo 816, alinea 318, artigo 278, caput 278, secao 51, capitulo 33, titulo 9, subsecao 5.
- Each node has `legislationIdentifier` (URN with `!fragment`) and `workExample[]`, one entry per version, carrying `legislationType`, `legislationDate`, `temporalCoverage`, `legislationLegalForce` and `text`.
- The `text` field may contain inline LexML XML (`<lx:p>`, `<span xlink:href>`).

Real sample, `…;1988!art7_cpt_inc13`:

```json
{"temporalCoverage":"1988-10-05/2026-10-15","legislationLegalForce":"NotInForce","legislationType":"Original_Version",
 "text":"duração do trabalho normal não superior a oito horas diárias e quarenta e quatro semanais, …"},
{"legislationDate":"2026-10-16","legislationType":"Text_Change_Version",
 "legislationIdentifier":"urn:lex:br:federal:constituicao:1988-10-05;1988@2026-10-16!art7_cpt_inc13",
 "legislationConsolidates":{"name":"Emenda Constitucional nº 141 de 16/10/2026", …},
 "text":"duração do trabalho normal não superior a 8 (oito) horas diárias e 40 (quarenta) horas semanais, …"}
```

**Version types seen:**

- Renumbering
- Court_Decision
- Applicability_Suppression

**Reverse check (does normas know something Planalto lacks?)**

- normas links Lei 15.224/2025 to CC art. 931 and Lei 15.252/2025 to CPC art. 833 X (`Applicability_Suppression_Version 2025-11-04`).
- Reading both laws on Planalto shows these are **indirect-effect relations**: an exception regime and penhorabilidade above 20 salários mínimos. They are not textual amendments, so Planalto's text is not stale.
- normas carries richer efficacy metadata, which is worth ingesting as annotations.

**Accuracy defect found: version dated by publication, not vigência.**

- normas versions the new CF art. 7 XV ("repouso semanal remunerado de 2 (dois) dias…") as of **2026-10-16**, and closes the old text as `NotInForce` on 2026-10-15.
- But EC 141 art. 10 says: *"entra em vigor: I - após decorridos 2 (dois) meses de sua publicação, em relação à alteração … no inciso XV do caput do art. 7º"*.
- LexML Parte 2 §12.1 says a version date is the *entrada em vigor* date. So normas violates its own spec here.
- Planalto handles it correctly (old text kept, plus "(Vide EC 141) (Vigência)").

**Other API notes**

- **Fetch by fragment is not supported:** `…/normas?urn=…;1988!art7_cpt_inc13&tipo_documento=maior-detalhe` returns the 74-byte stub `{"urn": "…!art7_cpt_inc13"}`.
- Without `tipo_documento`, or with `@date` in the URN, the API returns 400.
- **So:** fetch the whole norm and index locally.
- No ETag or Last-Modified on API responses (`Age:` header only, a CDN cache of about 5 min). Pull and hash instead.

## 3. LexML URN for dispositivos

**Spec sources:**

- Parte 2 (URN): <https://projeto.lexml.gov.br/documentacao/Parte-2-LexML-URN.pdf>
- Parte 3 (XML Schema / ids): <https://projeto.lexml.gov.br/documentacao/Parte-3-XML-Schema.pdf>

**Grammar.** Parte 2 gives `urn:lex:<local>:<autoridade>:<tipo>:<data>;<id>[@<versao>][~<forma>]!<fragmento>`. The normas.leg.br parser splits in exactly that order: `!` → fragment, `~` → language/form, `@` → version.

- Base examples: `urn:lex:br:federal:constituicao:1988-10-05;1988`, `urn:lex:br:federal:lei:2002-01-10;10406`, `urn:lex:br:federal:decreto.lei:1943-05-01;5452`.
- Fragment examples from Parte 2 §11: `…;126!art5_par2`, `![art6,art10]` (range), and a comma-separated **list** of fragments. Semantics map to XPointer `id('art5_par2')`.
- Version (Parte 2 §12.3): `@<data>` = start of vigência, or `inicio.vigencia`, `versao.original`, `multivigente`. Reference URNs also allow `versao.vigente.em;<data>`. Example seen: `…;1988@2026-10-16!art7_cpt_inc13`.

**Partition ids (Parte 3 §5.3–5.4, Tables 2–3)** are concatenated from the top level down:

| Level | id | Example |
|---|---|---|
| Parte | `prtN` | `prt1` (Parte Geral = sequential 1) |
| Livro / Título / Capítulo / Seção / Subseção | `livN` / `titN` / `capN` / `secN` / `subN` | `prt2_liv1_tit6_cap1_sec2_sub1` |
| Non-LC95 grouping (e.g. CC "Subtítulo") | `aghN` | `prt2_liv2_tit2_agh1` |
| Artigo / Caput | `artN` / `cpt` | `art5_cpt` |
| Parágrafo | `parN` | **parágrafo único = `par1`** (`art8-1_par1`) |
| Inciso / Alínea / Item | `incN` / `aliN` / `iteN` | `art39_cpt_inc1_ali2_ite1` |
| Generic | `dpgN` | `art5_par3_dpg2` |

- Roman numerals and letters become Arabic numbers. Letter suffixes become `-N`: Art. 3º-A-A → `art3-1-1`; Cap. IV-A → `cap4-1`.
- Incisos of the caput go under `_cpt_`; incisos of a paragraph do not (`art20_par2_inc2`).

**normas.leg.br deviates from Parte 3:**

- It uses `par1u` for parágrafo único (96 occurrences).
- It appends `,<sigla>-<n>-<date>` to inserted dispositivos (e.g. `art7_par2,emc-141-2026-10-16`, `art103-1,emc-45-2004-12-08`, `ali1,emr-…`). That clashes with Parte 2's comma = fragment-list syntax.
- **Recommendation:** mint our own ids per Parte 3 and store normas' fragment as `alias`.

**LexML portal**

- `https://www.lexml.gov.br/urn/<URN>` returns 200 HTML (2.44 MB) and **ignores the fragment**: same bytes for the base URN and for `!art5_cpt_inc10`.
- The SRU search API (`/busca/SRU?...`) returned a **"Verificação de segurança — Senado Federal" bot challenge** to curl. Treat it as unusable for automation.

- **Latest EC as of 2026-10-20: EC nº 141, de 16.10.2026.** "Altera o art. 7º … reduzir a duração máxima semanal do trabalho e prever 2 (dois) dias de repouso semanal remunerado". Published DOU 16.10.2026, extra edition.

| Event | When |
|---|---|
| DOU extra edition | Fri 16/10 |
| `quadro_emc.htm` Last-Modified | Fri 16/10 17:46 GMT |
| `emc140.htm` / `emc141.htm` Last-Modified | Mon 19/10 16:15 / 16:22 |

- Corroboration: LawCodex retrieved Planalto on 2026-10-12 and has 145 EC files (139 EC + 6 ECR), consistent with EC 139 being the latest before 16/10.
- Typical lag over many ECs: **UNVERIFIED**.
- **Suggested schedule:** daily job (cheap with ETag 304s), plus a "pending" state when the EC index has an EC that the compiled CF does not yet cite.

**Why vigência matters (EC 141).** Art. 10 makes the XV change effective 2 months after publication. Arts. 3 and 6 add phased effects (42 h after 2 months, 40 h after 14 months), even though XIII's new wording is "in force" textually. ctresb/leis adds a manual warning about exactly this. The schema needs `vigencia_inicio` per version plus a link to the amending act's transitional rules.

## 6. LC 95/1998 (técnica legislativa)

Fetched from <https://www.planalto.gov.br/ccivil_03/leis/lcp/lcp95.htm>.

**Art. 10** (quoted from the fetched text):

- I: article = "Art.", numbered **ordinal up to the ninth, cardinal from then on**.
- II: articles split into parágrafos or incisos; parágrafos into incisos; incisos into alíneas; alíneas into itens.
- III: "§", ordinal up to the ninth, then cardinal. A single paragraph is written out as "parágrafo único".
- IV: incisos in Roman numerals, alíneas in lowercase letters, itens in Arabic numerals.
- V: articles group into Subseções → Seção → Capítulo → Título → Livro → Parte.
- VI: Capítulos, Títulos, Livros and Partes in UPPERCASE with Roman numerals. Partes may be "Parte Geral / Parte Especial" or ordinal words written out.
- VII: Seções and Subseções in Roman numerals, lowercase, bold.
- VIII: groupings like Disposições Preliminares/Gerais/Finais/Transitórias are allowed.
- **Full hierarchy:** Parte > Livro > Título > Capítulo > Seção > Subseção > Artigo > (caput) > Parágrafo > Inciso > Alínea > Item.

**Art. 12, III** (as amended by LC 107/2001):

- b) **no renumbering** of articles or higher units. A new unit takes the previous number plus **capital letters in alphabetical order** (Art. 7º-A, 7º-B; Art. 3º-A-A exists in LexML examples).
- c) the numbers of revoked, vetoed, unconstitutional or suspended dispositivos may **not be reused**, and the marker ('revogado', 'vetado', …) must remain.
- d) "(NR)" marks an article that was reordered internally.
- Sole paragraph: "dispositivo" = artigos, parágrafos, incisos, alíneas or itens.

**Deviations observed in pre-1998 and other norms:**

- **CLT (1943):**
  - `Art. 482 - Constituem justa causa…: a) ato de improbidade; b) …`: dash after the number, and **alíneas directly under the caput with no incisos**.
  - TÍTULO / CAPÍTULO / SEÇÃO used (14 TÍTULOs, 148 SEÇÃO headings).
  - Renumbering happened historically: 1 "Renumerado" annotation in CLT, 18 in CF.
- **CTN (1966):** `LIVRO PRIMEIRO`, `LIVRO SEGUNDO` (ordinal words, not Roman numerals). Articles otherwise follow `Art. 9º … I - …`.
- **CC (2002):**
  - Uses **SUBTÍTULO** (16 occurrences), which LC 95 does not provide for (LexML maps it to `agh`).
  - Ordinals are written as `<sup><u>o</u></sup>`.
- **CF (1988):**
  - Has letter-suffixed articles (`103-A`), inserted paragraphs (`§ 4º-A`) and inserted incisos (`inc78`, `inc79` added by ECs).
  - CF art. 5 runs to inciso LXXIX.
  - The ADCT is a separate norm in LexML/normas.
- Planalto also shows `Art. 1°` (degree sign) in the CDC.
- **Parser rule:** a dispositivo can hold alíneas directly. Accept `º|°|o|<sup>o</sup>` ordinals, `-|–` separators, and `-A…-Z`/`-A-A` suffixes.

## Accuracy checks to build (derived from the findings)

0. **API contract guard (normas.leg.br is undocumented).** On every run, assert the response shape: node count within range, `workExample`/`legislationIdentifier` present, and the version-type vocabulary known. On failure, fail the job instead of publishing.
1. **Text diff Planalto vs normas.leg.br, per dispositivo, for the CF.** Expect zero diffs except known deferred-vigência cases; alert on anything else.
2. **Amender coverage.** For each norm, compare the set of amending acts cited on Planalto against normas `legislationConsolidates` and the Câmara compilation. A missing amender on one side means stale data on that side. Count only "Redação dada / Incluído / Revogado pela" citations, not "Vide" ones, and ignore normas indirect-effect relations. This check found CPC Lei 15.484/2026 and CC Leis 15.040/2024 and 15.068/2024 missing from normas.
3. **EC catalogue gap.** Compare the max EC in `quadro_emc.htm` and in Senado `vides` against the max EC cited in the compiled CF. While the compiled CF lags, mark the mirror "pending".
4. **Vigência guard.** Whenever "(Vide …) (Vigência)" or "Produção de efeito" follows a dispositivo, parse the amending act's vigência clause and store the pending wording with its start date.
5. **Structural invariants.**
   - Article numbers increase monotonically, with letter suffixes allowed and no reuse (LC 95 art. 12 III c).
   - Every revoked or vetoed label survives.
   - Counts per type stay within ±N of the previous run (CF: about 278 articles, 1,298 incisos, 816 parágrafos per normas).
6. **Parser hygiene tests** on fixtures from each code:
   - cp1252 decoding and `&#150;` handling
   - removal of strike/`<s>`/line-through
   - ordinal variants
   - CLT alíneas under the caput
